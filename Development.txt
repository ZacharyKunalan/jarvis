───────────────────────────────────────────────────────
  SESSION 1 — Project Setup & Architecture
───────────────────────────────────────────────────────

Goal: Get a basic skeleton running.

Built the initial project structure with main.py and
logic.py. Defined the core loop: listen → process →
respond. Added a placeholder ask_ai() function that
echoed input back so the loop could run end-to-end
before real AI was connected.

Issue: ImportError on startup — main.py was importing
ask_ai from logic.py before the function existed.
Fix: Added the placeholder immediately so imports
resolved cleanly.

Stack at end of session:
  - main.py (controller loop)
  - logic.py (functions)
  - timetable.json (schedule data)

───────────────────────────────────────────────────────
  SESSION 2 — Text to Speech
───────────────────────────────────────────────────────

Goal: Make Jarvis speak responses out loud.

First attempt used pyttsx3 — worked but sounded robotic
and low quality. Replaced with edge-tts using the
en-GB-RyanNeural voice which sounds significantly more
natural and British.

Issue 1: edge-tts saves audio to a file — used
os.system("start response.mp3") to play it, which
kept opening Windows Media Player instead of playing
silently in the background.
Fix: Switched to playsound for silent programmatic
playback.

Issue 2: playsound 1.3.0 has a known Windows bug
with mp3 files — crashes on playback.
Fix: Pinned to playsound==1.2.2 specifically.

Issue 3: pygame was attempted as an alternative but
failed to install — Python 3.13 removed distutils
which pygame depends on at build time.
Fix: Abandoned pygame, kept playsound 1.2.2.

Note: A winsound fallback using .wav format was
documented in logic.py comments in case playsound
causes issues in future.

Stack at end of session:
  - TTS: edge-tts + playsound==1.2.2
  - Voice: en-GB-RyanNeural

───────────────────────────────────────────────────────
  SESSION 3 — Voice Input
───────────────────────────────────────────────────────

Goal: Replace typed input with real microphone input.

Installed openai-whisper, sounddevice, and numpy.
Added listen() to logic.py which records audio via
sounddevice, saves to a temp .wav, transcribes using
Whisper tiny model, then deletes the file.

Issue 1: Whisper requires FFmpeg for audio decoding
but it wasn't on the system.
Fix: Downloaded FFmpeg from gyan.dev and manually
added the bin folder to Windows PATH. winget was
unavailable on this machine.

Issue 2: Whisper defaulted fp16=True which crashes
on CPU-only machines.
Fix: Set fp16=False explicitly.

Issue 3: Fixed-length 5s recording felt unnatural —
Jarvis would cut off mid-sentence or wait too long
after you finished.
Fix: Extended to 7s as a temporary measure.

Stack at end of session:
  - STT: openai-whisper (tiny, local, CPU)
  - Audio: sounddevice + FFmpeg

───────────────────────────────────────────────────────
  SESSION 4 — Groq Integration (STT + LLM)
───────────────────────────────────────────────────────

Goal: Replace slow local Whisper and placeholder AI
with fast cloud-based alternatives.

Switched STT from local Whisper tiny to Groq's hosted
whisper-large-v3. Accuracy improved dramatically —
proper nouns, accents, and quieter speech all handled
much better.

Replaced placeholder ask_ai() with Groq's
llama-3.1-8b-instant for real AI responses.
Response speed went from 3-5s to under 1s.

Issue 1: llama3-8b-8192 was the first model attempted
but Groq had decommissioned it.
Fix: Swapped to llama-3.1-8b-instant.

Issue 2: Timetable routing was too aggressive — the
keyword "today" was in the trigger list which caused
almost every sentence to route to timetable logic
instead of the AI.
Fix: Removed "today" from timetable keywords, made
routing more specific.

Issue 3: API key security — key was initially
hardcoded.
Fix: Moved to .env file using python-dotenv.

Stack at end of session:
  - STT: Groq whisper-large-v3
  - LLM: Groq llama-3.1-8b-instant
  - Env: python-dotenv

───────────────────────────────────────────────────────
  SESSION 5 — VAD & Smart Listening
───────────────────────────────────────────────────────

Goal: Replace fixed-length recording with smart
voice activity detection so Jarvis stops listening
when you stop talking.

Replaced the fixed 7s recording with webrtcvad-based
capture. Records in 30ms chunks, detects speech vs
silence in real time, stops automatically after
~1 second of silence post-speech.

This made the conversation feel natural — no more
waiting for a timer to expire.

Issue: Single-word responses like "exit" were being
dropped — the listen() function had a minimum word
count check of 2 that silently discarded them.
Fix: Lowered minimum to 1 word so short commands
like "exit", "yes", "stop" all get through.

Stack at end of session:
  - Audio input: webrtcvad (30ms chunks, VAD-based)

───────────────────────────────────────────────────────
  SESSION 6 — Wake Word & Exit Fix
───────────────────────────────────────────────────────

Goal: Add "Hey Jarvis" wake word so it only listens
when called, and fix the exit command reliability.

Split listen() into two functions:
  - listen_for_wake_word() — fast, accepts 1 word,
    shorter silence timeout, always running
  - listen() — full command listener, used only
    after wake word detected

Exit issue: "exit" was being heard but the break
statement only escaped an inner loop, not the full
run_jarvis() function. The program kept looping back
to listen_for_wake_word() which silently swallowed
any further "exit" attempts.
Fix: Changed break to return so the entire function
exits cleanly. Added exit detection at both the
wake word stage and command stage.

Also added inner command loop — after Jarvis responds,
it stays awake and listens for a follow-up command
rather than immediately going back to sleep. Goes
back to wake word mode only after silence.

Issue: "Listening for command..." printed twice per
cycle — once in main.py and once inside listen().
Fix: Removed the duplicate print from listen().

Stack at end of session:
  - Wake word: keyword match on "jarvis" in transcript
  - Exit: works from any point in conversation

───────────────────────────────────────────────────────
  SESSION 7 — Tkinter UI
───────────────────────────────────────────────────────

Goal: Add a visual interface with an animated orb
that reflects Jarvis's current state.

Built ui.py — a dark sci-fi themed desktop window
(360x520) using tkinter. Aesthetic: deep navy/black
background, electric cyan accent, Courier New font.

Orb animation has 3 states:
  - STANDBY: slow breathing pulse, slow ring rotation
  - LISTENING: faster pulse, brighter rings
  - SPEAKING: rapid bursts, all rings fully lit

State sync: main.py writes current state to
jarvis_state.txt every time it changes. UI polls the
file every 200ms and updates animation + status text.

Timetable panel: click [ TIMETABLE ] to open a panel
showing the schedule. Initially showed today only.

Issue: ui.py filename was saved as "Ui.py" (capital U)
on Windows — Python import is case-sensitive on some
systems and the import failed.
Fix: Renamed to ui.py (lowercase).

Issue: Closing the window on "exit" command — tkinter
must be destroyed from the main thread, not the voice
thread.
Fix: Added shutdown() function using
root.after(0, root.destroy) which safely queues the
destroy call on the main thread.

Stack at end of session:
  - UI: tkinter (animated orb + status + timetable)
  - State sync: jarvis_state.txt (polled every 200ms)

───────────────────────────────────────────────────────
  SESSION 8 — Voice Add to Timetable
───────────────────────────────────────────────────────

Goal: Allow adding events by voice naturally, e.g.
"Add dentist at 3pm on Thursday."

Added is_add_timetable() to detect add-intent phrases.
Added parse_timetable_entry() which sends the voice
command to Groq LLM with a strict system prompt
instructing it to return only a JSON object with
day, time (24hr), and event name.
Added add_to_timetable() which writes the parsed
entry to timetable.json, sorts by time, and confirms
back by voice.

Issue 1: Saying "tomorrow" saved a key literally
named "tomorrow" in the JSON instead of the actual
weekday name.
Fix: Added _resolve_relative_days() which converts
"tomorrow" → actual weekday (e.g. "wednesday") and
"today" → current weekday before the text is sent
to the LLM.

Issue 2: The docstring in parse_timetable_entry was
placed after the first line of code due to a bad
sed injection, which caused silent misbehaviour.
Fix: Moved docstring to the correct position
immediately after the def line.

Issue 3: AI was sometimes interpreting "add gym" as
a request to notify someone or book an appointment
rather than adding to the local timetable.
Fix: is_add_timetable() now intercepts these phrases
before ask_ai() sees them.

Stack at end of session:
  - Timetable: voice add + JSON persistence
  - Relative days: resolved before LLM parsing

───────────────────────────────────────────────────────
  SESSION 9 — Timetable Panel (All 7 Days)
───────────────────────────────────────────────────────

Goal: Show all 7 days in the timetable panel instead
of just today, with a scrollbar.

Rebuilt the timetable panel section of ui.py:
  - All 7 days shown in order Mon → Sun
  - Today highlighted in cyan with a ▶ marker
  - Other days shown in grey
  - Scrollable with a side scrollbar
  - Auto-scrolls to today on open
  - "No events" shown in grey for empty days

Added _watch_timetable() file watcher which checks
timetable.json modification time every second. If the
file changed and the panel is open, it auto-refreshes
the content live — no need to close and reopen.

SETUP & DEPENDENCY FIXES:
  - Cloned repo and set up Python venv
  - Fixed requirements.txt formatting bug (python-dotenv
    and pyttsx3 merged onto one line)
  - Resolved webrtcvad incompatibility with Python 3.14
    by creating a custom compatibility wrapper
    (webrtcvad.Vad class mapped to _webrtcvad functions)
  - Installed Microsoft C++ Build Tools for native
    package compilation
  - Installed setuptools to fix pkg_resources error

WAKE WORD:
  - Replaced Whisper-based wake word detection with
    openWakeWord using hey_jarvis_v0.1.onnx model
  - Runs fully locally, no API key required
  - Much faster response, fewer false positives
  - Added 0.5s delay after wake word before listening
    to allow mic stream to settle

WEATHER:
  - Added Open-Meteo weather feature (free, no API key)
  - Hardcoded to Guildford, Surrey (lat/lon)
  - Supports today and tomorrow queries
  - Returns condition, high/low temp, rainfall
  - Added is_weather_query() intent detector
  - Routed through main.py intent system

WHISPER IMPROVEMENTS:
  - Added filler phrase filter to _transcribe() to
    block hallucinated phrases like "thank you"
  - Added context prompt to Whisper with common
    command words to reduce misrecognition
  - Switched to whisper-large-v3-turbo model
  - Explicitly set USB mic as device 1 in _capture_audio
  - Added minimum frames check to avoid sending
    tiny audio clips to Whisper
  - Added "is it" to EXIT_WORDS (common mishear of exit)

TIMETABLE:
  - Added null time check in parse_timetable_entry()
    prompt so LLM returns null instead of guessing
  - Added follow-up listen in main.py when time is
    missing — Jarvis asks for time then immediately
    listens for the answer

UI OVERHAUL (ui.py rebuilt from scratch):
  - Window size increased to 460x660
  - System stats bar added (SYS/NET/AI/MIC)
  - Subtitle added under logo
  - Larger orb (44px radius) with inner glow ring
  - Second counter-rotating arc added for depth
  - 32 tick marks with varying sizes (was 24)
  - Blinking cursor next to status text

  - Brighter colour palette throughout
